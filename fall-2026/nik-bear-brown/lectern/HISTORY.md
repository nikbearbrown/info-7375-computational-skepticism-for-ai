# Lectern history: what was added when, and why

## Executive summary

**What this is.** A day-by-day record of how the Lectern folder was built up: what was added each day, what changed, and the reason. **Why read it.** The folder looks like a pile of scripts because it grew one need at a time, and the order of those needs is the explanation: first a collector and a filter, then audits of the filter, then a ranking of companies, then a way to publish only what changed, then posting, then measuring whether the jobs turn over. **What it shows.** In about three weeks the project went from one collector to a pipeline with seven steps, and almost every step was added because the step before it produced a number that could not yet be trusted. This file is a companion to `../FRICTIONAL.md`, which tells the same story from the author's side; this one stays with what changed in this folder.

## How to keep this file

Add an entry whenever something in `lectern/` is added, changed or removed: the date, what, and why, in the same change. Source for the past entries: `git log` for this folder and the entries in `../FRICTIONAL.md`. Dates are commit dates. Write what happened, including what failed; never write a result nobody ran.

## How it was built up, in order

1. **A collector and a filter** (2026-09-26): read the boards, keep what looks like teaching.
2. **Audits of the filter** (09-26): sample the rejects, then audit by job function.
3. **A different question** (09-26): rank companies by whether they want this work, not postings by fit.
4. **More sources** (10-08): the big four, which have no simple feed.
5. **Publish only what changed** (10-18): new, changed, gone, against a remembered state.
6. **Do the jobs turn over?** (10-18): churn.
7. **Beyond job boards** (10-18): business-school faculty listings.
8. **Posting** (10-19): new listings go to Discord on their own; lab pages for a person to look at.
9. **Other forms** (10-19 on): the same pipeline as n8n workflows, tested against this one; a CrewAI form planned.

## Before this folder

The collector existed before this folder did. According to the 2026-09-26 entry in the log, the Branding and AI class folder already held the collector, the watch list, the filter, the applicant-tracking notes and the CV facts; this folder, named master that day, started with none of it. Earlier single-company versions are in `../greenhouse-watch-demo/` (the Reallocation Engine's watcher run on one board, begun 2026-09-24) and `../figma/` (the first single-company iteration: a saved board, a scan, the kept postings).

## 2026-09-26: the folder is made the master, and the filter is audited

- **Added:** `collect.py`, `keywords.json`, `sources.json`, `ATS.md` and `sync.sh` (the folder becomes the master for three classes; the copy mechanism is `sync.sh`, which also has a `--check` mode that changes nothing).
- **Added:** `audit_rejects.py`, a reproducible random sample of the 3,358 rejected postings (seed recorded). **Why:** nobody had looked at what the filter threw away. **Found:** an audit aimed at missed jobs found the opposite problem: `education` was in 618 of 618 Anthropic postings (a salary footer), and the topic-word rule was keeping recruiters.
- **Added:** `audit_titles.py` and `title_families.json`. **Why:** reading postings is the wrong unit; there are far fewer job functions than postings. **Found:** 18 families cover everything, and the audit's own first pass was wrong: it counted "training" as a teaching word, but at an AI company it means training a model. The error was reported, not quietly fixed.
- **Changed:** `keywords.json` to v0.4.0 and `title_families.json`. **Why:** the target became "makes the materials", in any kind of company, whatever it is called. A two-part body rule (a make-materials phrase and a named audience, both required) was built, failed twice on measurement, and was cut down; every cut phrase is recorded in the file with the count that cut it. A posting for a Learning Experiences Creator had been rejected for the want of one word. Result: 97 kept of 3,446.
- **Added:** `demand_report.py`. **Why:** the unit of analysis was wrong; a posting is evidence that a company decided the work is worth paying for, so the report ranks companies on five kinds of evidence. **Found:** Google's absence from the table was an artefact (no public feed), not a lack of demand; a person reading its careers site found 20 education roles on the first page. That check, its URL and its date went into `sources.json`.
- **Evidence:** the five 2026-09-26 entries in `../FRICTIONAL.md`.

## 2026-10-18: a publishing step, a turnover measure, and a faculty reader

- **Added:** `publish_delta.py`, `runs/published-state.json` and the first delta (`runs/2026-10-18/`: 42 new, 7 changed, 9 gone). **Why:** only what changed since the last published run should be published, not everything. A source that could not be read today never closes a posting; it is "unknown".
- **Added:** `churn.py`. **Why:** are these real jobs that turn over, or postings that sit there? It measures age, flow between snapshots and re-posts. Closed is not hired.
- **Added:** `faculty_feed.py` and `faculty_config.json`. **Why:** business-school faculty roles that mention AI. The universities' own job systems mostly cannot be read by script, so it reads the Chronicle of Higher Education and Inside Higher Ed keyword feeds. First run: 1,727 items read, 14 matched, 0 errors. It was first built in a private folder with alerts to a private channel, an assumption of the assistant's that was corrected: the channel is meant to be public.
- **Changed:** `keywords.json` (v0.5.1, v0.5.2): a connector rule for roles that own a big institutional relationship, an account or partnership word in the title and a higher-education institution in the body, widened the same day to marketing, adoption and enterprise-account titles. Each addition was measured against the corpus first; a miscount of one role family (27 against 38) was found and corrected on the record.
- **Changed:** `sources.json`: Stripe and Writer came off the watch list, at Professor Bear's word; the reason first recorded was wrong and was corrected to his own (not directly applicable to improving education through AI, not a judgment that they are bad). Watch list: 16 boards.
- **Added:** `test_publish_delta.py`, `test_churn.py`, `test_connector_rule.py`; `.gitignore` (full snapshots and raw payloads stay local). `sync.sh` gained `collectors/` and `publish_delta.py`.
- **Ran:** a collection of 17 of 18 boards (HubSpot returned HTTP 404): 3,243 postings, 88 kept. A bug in `publish_delta.py` showed up the same day: it reported 47 postings as "changed" only because the filter had started writing a new field; fixed, with a test.
- **Evidence:** the two 2026-10-18 entries in `../FRICTIONAL.md`.

## 2026-10-20: this folder is explained

- **Added:** `README.md` (what each file is, the pipeline, what is shared, what is not here) and this file. **Why:** a visitor to the folder on GitHub saw a flat pile of scripts with no map. The honest answer to "why is it organised like this" was that it was not organised, it accumulated; the layout stays as it is for now (moving files means re-syncing three repositories), and the README is the map.
- **Changed:** the folder was reorganised into `config/`, `collect/`, `publish/`, `audit/`, `tests/`, `ops/` and `notes/`, with `lectern_paths.py` added so no script guesses where its files are. **Why:** Professor Bear: this is a teaching course, and a flat pile of scripts is not what proper code looks like. The folders follow the pipeline (rules in, sources read, what changed published, the filter audited) and teach three habits: separate what you edit from what runs, separate reading from writing, and never let a script guess where its files are. **How it was done safely:** every script asks `lectern_paths.py` for its paths, so the same files run in the master's folders and in the other two classes' flat copies; `sync.sh` flattens on the way out. The five test files pass in the new layout, a simulated flat copy runs the scripts, and the n8n form's parity tests pass against it. **Not done:** the other two classes were not re-synced yet, and nothing was changed in Branding's graded folder.
- **Added: one list of targets, and a place for every other form.** `config/targets.json` now holds all 98 targets (6 active boards, 12 removed with their reasons, the big four, 9 with no data source, 21 schools, 45 research places) with their type, data links, reader and status; `sources.json`, the schools in `faculty_config.json`, the seeds in `biolabs.json` and the tables in `TARGETS.md` are generated from it by `ops/build_from_targets.py`, and the first regeneration reproduced the three config files byte for byte, which is the proof nothing was lost. `tests/test_targets.py` fails if any of them drifts. The n8n form moved to `forms/n8n/`, and `forms/` has a folder and README for each planned form (a Pydantic AI judge, CrewAI as a Flow and as a Crew, LangGraph, Muse, Grok Bot, Dots) with `forms/PLAN.md` holding Professor Bear's plan. Shared plumbing: `compare/` (a check that a run uses the one output format, a comparison against the reference run, a heartbeat that does not pass when no tool has logged) and `logs/`. **Why:** Professor Bear: the Python is the source of truth for the project's point, the companies looked at, and every other form reads the same list instead of keeping eight versions of it; each form owns only what is specific to it. **Not done:** every form folder is a placeholder; the GitHub heartbeat Action is not written; the removed targets are not yet shown to a discovery agent because no such agent exists.
- **Changed:** `config/sources.json`: HubSpot came off the watch list, at Professor Bear's word: its education is product training for HubSpot, not educational AI, and it did not look relevant. Its board had also returned 404 since 2026-10-18. Miro was kept for now (he wants to research it first). Watch list: 6 boards (Anthropic, Figma, Miro, OpenAI, Notion, Canva), all read.
- **Changed:** `config/sources.json`: Vercel, Webflow, Airtable, GitLab, Twilio, Netlify, Jasper AI and Supabase came off the watch list, at Professor Bear's word. **Why:** they are not really educational AI (institutional or university AI): more software products than true educational tools, and not tools that could be the central part of a course unless the course is on that tool. The reason is recorded in the file's `removed` block. Watch list: 7 boards (Anthropic, Figma, HubSpot, Miro, OpenAI, Notion, Canva); HubSpot's currently returns 404, so 6 are read.
- **Added:** `collect/collectors/biolabs.py`, `config/biolabs.json` and `tests/test_biolabs.py`. **Why:** a student repository (Biojobs) had a lab scraper; Professor Bear asked to take what was useful. **Kept:** its data-signal keywords (RNA-seq, single-cell, Nextflow, HPC and so on, plus five added here), the directory-to-lab-to-people crawl, the portal and fundraising deny lists, tracking-parameter stripping, and never parsing an error page. **Changed on purpose:** it reads `robots.txt` first (the original never did), says what it is instead of sending a browser's User-Agent, decodes no hidden or obfuscated email addresses and drafts no outreach (those belong to Professor Bear), and writes one lab record per page into the local, untracked `lab-records/`. **Found:** a long User-Agent string made Harvard Medical School's server answer 403 while a short honest one gets 200; the Chan School page returned degree programmes until the filter learned to skip them; 4 of its 7 seeds no longer answer. 8 tests pass.
- **Moved into this folder:** `TARGETS.md`, `lab-outreach/`, the n8n form (as `n8n/`) and `faculty-runs/`. **Why:** Professor Bear: everything about Lectern belongs in the Lectern folder or one of its subfolders; the folders at the level above are about the assignments. The profile (assignment 06), the CV facts, the early iterations and `SYNC.md` stay at the class level because the other two classes share them.

## 2026-10-26: two gates after the keywords: allowed countries, and no K-12

- **Changed:** `config/keywords.json` to v0.6.0, with `location_rule` and `k12_rule`. **Why:** Professor Bear read a listing that fit the keywords and was no use to him: a K-12 education account manager in Seoul, from a design-software company. He said, by voice: keep it to English-speaking countries, unless it is France, Italy, Brazil or Portugal; and no K-12. The keywords can only say what to keep, so the rule is two gates that run after them and can only drop a posting the keywords would have kept; every old reject keeps its old reason, and a drop says why (`country not allowed: South Korea`, `K-12 role: 'k12' in the title`). **The choices that are his, and the default taken for each:** English-speaking means the United States, United Kingdom, Canada, Australia, New Zealand and Ireland (India, Singapore, the Philippines, Hong Kong and South Africa are not in, and the comment says what each would bring back); a location that names no country is kept and marked; a posting in several places is allowed if any one is; K-12 is read in the title only, in any spelling, plus grade bands (the body is not read, and the comment says which four postings that would drop).
- **Changed:** `collect/collect.py`: `judge()` applies the two gates after the keyword decision; new `fold()`, `places_of()`, `where()` and `k12_hits()`. A kept record gains `matched.location`, which is empty unless the location named no country (so the change report does not call every kept posting changed, the trap of 2026-10-18).
- **Added:** `audit/audit_gates.py` (runs the filter twice over saved responses, with and without the gates, and lists every posting only the gates dropped; or checks the place reader against the country codes a big snapshot reports) and `tests/test_gates.py` (17 tests, including the Seoul posting, a posting in several places, `Lebanon, PA` against `Beirut, Lebanon`, `New Mexico` against `Mexico`, and `K8` the Kubernetes abbreviation not being K-12).
- **Measured before adding** (numbers in `keywords.json`): on the 3,243 saved ads of 2026-10-18 the keywords alone keep 92, the gates 82: ten dropped, all by country (Japan 4, South Korea 2, Germany 2, Indonesia 1, Mexico 1), eight of them on today's six boards. On a snapshot of 84,282 postings (titles and places only) the place reader names a country for 82,327 and agrees with the boards' own country codes on 37,458 of 37,470; the title keeps 1,056 before and 886 after (144 by country, 24 by K-12, 2 by both). Of the 91 listings already published, ten would now show as gone.
- **Found, and not fixed:** Canva's "District Education Advocate, South Korea" of 2026-10-18 was the same job as the "K12 Education Account Manager" Professor Bear saw, before it was retitled; its ad says "school system" and never "K-12", so the K-12 rule alone would have missed it and only the country rule caught it. The body is not read for K-12 on purpose: three OpenAI education roles that also cover higher education would go.
- **Changed:** `forms/n8n/`: `shared/lib/judge.js` has the same two gates, the fixtures cover them, and `tools/parity_location.py` compares the Python and JavaScript readers on every location line and title of the snapshot (all agree). The five workflows pass headless; the filter agrees with the Python on all 1,869 postings of the six boards on the watch list (60 kept by each).
- **Not done:** `sync.sh` was not run, so the other two classes still have v0.5.2 (`collect.py` and `keywords.json` are shared; `audit_gates.py` is not in the shared list); nothing was posted or pushed. Rule 0 asks for `./lectern/ops/sync.sh --check` and then `./lectern/ops/sync.sh` before this is called finished.
- **Evidence:** the 2026-10-26 entry in `../FRICTIONAL.md`; `forms/n8n/test-results/parity-2026-10-26.txt`.

## 2026-10-28: a second channel for early-career game, engine and real-time jobs (posting off)

- **Added:** a second judge and a second destination. Professor Bear pasted a list of Unity, Unreal and Godot job titles (an AI-compiled draft, not fact-checked) and said any game job an early-career person with some engine experience could take should go to a new Discord channel, #games-3d-simulations, with posting off until he says go. `config/keywords.json` v0.6.1 gains `engine_rule` (phrases in five groups, early-career and not-early-career words, false friends, `"posting": "off"`); `collect/engine_jobs.py` judges a posting from its title and place and gives a reason for every decision; `publish/games_feed.py` is the poster; `audit/audit_engine_titles.py` measures every phrase; `tests/test_engine_jobs.py` (14) and `tests/test_games_feed.py` (12). `notify.post()` gained a `channel` argument (default unchanged). **Why a separate judge:** these are not education jobs and must never enter the #professor-bear stream, so `collect.judge()` and every existing post are unchanged. The country rule and the K-12 rule apply here too.
- **Measured before adding** (numbers in the `engine_rule` comment): on the ai-jobs snapshot of 2026-10-24 (84,282 postings, titles and places only) 163 titles carry a phrase of a group that is on; 104 name a level that is not early career, 22 are dropped by the country gate, 23 name no level and are held back, **14 would be posted** (11 Epic Games internships; an Associate Game Designer each at Hasbro, Naughty Dog and Nintendo). Lectern's own saved boards (3,243 postings) contain **none**: no watched company is a game studio. Zero titles today for godot, unreal engine, ue4, ue5, level designer, combat designer, virtual production, digital twin and more, so those cannot add noise yet. Bare words were tried and not added (`game`, `games`, `gaming`, `designer`, `producer`, `artist`, `tester`, `qa`, `engine`, `3d`, `graphics`, `studio`, `vr`, `xr`, `animator`), each with its noise in the rules file. Two false friends are blanked: `Unity Catalog` (a data product) and `Design Systems Designer`.
- **How early career is read, and how well:** from the title only, because the feed keeps no ad text. A veto word (`Senior`, `Lead`, `Principal`, `II`, `Manager`, `Director`) wins over an early word, so `Associate Director` is a director. It agrees with the feed's own seniority label on 162 of 163 matched titles (the one difference is a `Manager`, and this rule is right), but the two rules are of one family, so that is consistency and not proof. I read the 14 that would be posted; all are plausible entry points. **What it cannot do:** a title that states no level may be junior-friendly or may want five years, and 'some engine experience' lives in the ad text. The 23 with no level word are held back, not posted.
- **Where it reads from, and why not Lectern's boards:** Lectern reads six boards and none is a studio. The ai-jobs daily snapshot is the only source with many boards, a place for every posting and a title family. **Its game coverage is thin:** of 51 game, film and engine companies on its list that I checked, 17 have a board it can read (Epic, Riot, Roblox, Scopely, Supercell, Nintendo, Take-Two, Naughty Dog, Hasbro and others); Unity, Electronic Arts, Ubisoft, Activision and Blizzard are not readable yet, and studios post mostly senior jobs. So 'any game jobs' means any on those 17 boards, today about 14.
- **Rights, for Professor Bear to decide:** the post carries the title, company, place and link of the employer's own public posting, the same fields as the #professor-bear posts. The boards are the public job-board APIs the employers publish. But the ai-jobs repository says in its own `DATA-PROVENANCE.md` that public accessibility is not a grant of redistribution rights and that a field allowlist is not a rights clearance, and its policy today is that only counts and summaries leave its server; a release of individual postings needs a source-by-source review and a dated record, which has not been done. A Discord post is a link to the original, not a copy of the ad, but it is a new outflow that those documents do not yet cover. This is not legal advice. Also unknown: who can read the channel.
- **Where posting would run, not decided and not set up:** the daily snapshot lives on the always-on server under the collector's own user, whose home the Lectern user cannot read. Options: run the poster as a step of the collector's daily run (needs a copy of these rules there); let the collector export a small file the Lectern user can read; or run it by hand on the Mac from a snapshot that is days old. Whichever is chosen, only that place posts; this change deploys nothing and touched no server. `daily.sh` is not changed. First live run, whoever runs it: `--baseline` to skip today's backlog, or `--post-all` to post it.
- **Not done:** posting (off by design; no test post was sent and no webhook was read); `sync.sh` (the other two classes do not have `engine_rule` or the 0.6.0 gates); a push. The n8n form ignores `engine_rule` (its copy of the rules is whole); both n8n copies were regenerated and re-tested.
- **Evidence:** the 2026-10-28 entry in `../FRICTIONAL.md`; `forms/n8n/test-results/parity-2026-10-28.txt`; `audit/audit_engine_titles.py --jobs-jsonl <jobs.jsonl>` reproduces every number above.
