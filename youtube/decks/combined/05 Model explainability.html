Model explainability

Why a faithful explanation of the model is not a fact about the world, and what to check

A model can explain itself fluently and still leave a reader believing something false about the world. This deck covers what SHAP, LIME and counterfactual explanations actually show, how a Shapley value is computed and what its four axioms guarantee, and why transparency, explainability and interpretability are different properties. It defines thirty-one terms along the way, each tagged as explained in the course reading; the course exam lists mark LIME and SHAP as learn-them-but-not-on-the-exam.

Conceptual illustration

The question

The explanation felt right

Source: Chapter 5, opening case and Figure 5.1; review deck “Chapter 5: Model Explainability”.

A screening tool tells a radiologist: high risk of malignancy, 0.84, driven by a texture pattern and a regional asymmetry. She checks, both are present, she recommends biopsy, and the biopsy is benign. This is a composite case, labelled as one, and the mechanism it shows is documented: imaging models learn shortcuts, and explanations report them faithfully. The tool did not lie about itself, yet the explanation gave a doubtful decision a coherence it did not deserve.

Conceptual illustration

The central claim

The explanation describes the model

Source: Chapter 5, opening and “Where this leaves us”; review deck “Chapter 5: Model Explainability”.

An explanation sits at the end of a chain from the world to the model to the explanation. Methods such as SHAP and LIME describe the model faithfully, and nothing in them checks the link back to the world, yet a reader tends to carry the explanation across that link. The machine supplies speed and coverage, a faithful number on every prediction; the human supplies the doubt about what that number warrants. That doubt is called interpretive judgment.

Illustrative data

The fluency trap

Fluency trap, accurate but misleading, shortcut, post-hoc explanation

Source: Chapter 5, the opening case; “Where this leaves us”.

A fluent explanation is not evidence. In this illustration the explanation is true about the model, since X and Y did drive the score, and says nothing about whether X and Y mean malignancy in the world. A shortcut is a pattern that matches the label in training, 90 of 100 cases here, and fails in deployment, 30 of 100; those counts are invented to show the effect. A post-hoc explanation is worked out after the output and reports the shortcut faithfully without marking it as one.

Simulation (seeded)

What SHAP is

SHAP, internal accounting, Rung 1, Rung 2

Source: Chapter 5, “What SHAP is, and what SHAP isn’t”; Exam terms - compact list.

SHAP gives one number per feature for one prediction: income +0.073, debt-to-income +0.062 and zip code +0.035, which add up to the gap between the prediction, 0.72, and the average, 0.55. Those numbers are the model’s own accounting. They are real, and they say nothing about whether zip code is a proxy for anything or what would happen if it changed. SHAP sits on the first rung of Pearl’s ladder, association, so the intervention questions on the second rung are out of its reach; in the seeded simulation a hidden variable makes X and Y move together, while setting X by hand shows no effect on Y.

Computed

The Shapley value

Value function, coalition, marginal contribution, Shapley value

Source: Chapter 5, “The mathematics of Shapley values”.

A value function gives the model’s expected prediction when only some features are known: the average, 0.55, with none known, and the actual 0.72 with all known. A coalition is a subset of features treated as known, and three features make eight of them. A feature’s marginal contribution depends on who is already in; income adds between 0.06 and 0.09 depending on the coalition. The Shapley value averages that contribution over all six orderings, which gives 0.073 for income.

Computed

The Shapley value

Efficiency, Symmetry, Dummy, Additivity

Source: Chapter 5, “The four axioms”.

Four axioms pin down the Shapley value. Efficiency: the three values add up exactly to 0.17, the prediction minus the average, so nothing is left over and nothing is counted twice. Symmetry: features that do the same work get the same credit. Dummy: a feature that changes nothing gets zero, so a non-zero zip code value means the model uses zip code. Additivity, also called linearity: values for combined models are sums, so a forest can be explained tree by tree. None of the four promises that an attribution is causal or correct.

Computing it

Why exact values are estimated

Source: Chapter 5, “Computational shortcuts: from exact to approximate”; review deck “Chapter 5: Model Explainability”, “Exponential coalitions”.

Exact Shapley values need the model’s prediction for every subset of features: 8 subsets for three features, 1,024 for ten and over a billion for thirty. Sampling random orderings keeps the cost near the number of orderings times the number of features, so beyond about fourteen features it is cheaper, at the price of an estimate. The sampling size of 1,000 is illustrative. Four methods differ in cost, exactness and how they treat dependent features.

Simulation (seeded)

Computing it

Sampling, TreeSHAP, correlated features, conditional sampling

Source: Chapter 5, “Computational shortcuts” and “The correlated feature problem”; Aas, Jullum and Løland 2021.

Sampled estimates settle as more random orderings are drawn: the running estimate for income approaches the exact 0.073. TreeSHAP gets exact values for tree models by walking only the paths that change a prediction instead of trying every subset. Correlated features strain the method, because drawing each feature independently produces combinations that never occur in real data, and the model must extrapolate on them. Drawing the missing features conditionally stays on the data, but the Dummy axiom can then fail.

Illustrative data

Computing it

Same model, two answers

Source: Chapter 5, “The correlated feature problem”; review deck “Chapter 5: Model Explainability”, “Marginal or conditional” (figures illustrative).

The same model can split credit two ways. With marginal sampling zip code gets 0.19 and income 0.31; with conditional sampling zip code gets 0.04 and income 0.46; both total 0.50. Marginal asks what each feature contributes to the model’s behavior on average, and conditional asks what it adds given what is already known. Neither is wrong, and neither shows whether the model uses zip code as a stand-in, which is a question about the world.

Simulation (seeded)

Other methods

LIME, instability, off-manifold, counterfactual

Source: Chapter 5, “LIME, in a different shape” and “Counterfactuals are closer to what you actually want”.

LIME perturbs one input, records the model’s output, and fits a weighted straight line near it; the slope is the explanation. The perturbations are random, so the same input can give a different slope on each run, and most practitioners run it once. Perturbed inputs can also land where no real case exists, and the coefficient comes out either way with no warning. A counterfactual explanation states how the prediction would change if a feature had another value, such as income $5,000 higher; many changes can flip the decision, and the method picks one.

Conceptual illustration

Other methods

Where each method stops

Source: Chapter 5, “Counterfactuals are closer to what you actually want” (family table); Exam terms - compact list; review deck “Chapter 5: Model Explainability”.

Three families of explanation sit on two rungs of Pearl’s ladder. SHAP and LIME stay on the first rung, association: they describe how the model behaves. A counterfactual explanation reaches the second rung, intervention, because it states what the model would predict if an input were set to a value. Even that is the model’s answer; what the world would do is not reached, and that remaining gap is supervisory territory, not a defect a tool can patch.

Conceptual illustration

Explainable to whom?

Transparency, explainability, interpretability, Rudin

Source: Chapter 5, “Three words that don’t mean the same thing”; Rudin 2019.

Three words often used as synonyms name different properties. Transparency belongs to the system: its code, weights and data can be inspected. Explainability belongs to outputs: each comes with a reason. Interpretability belongs to a person: they can build a mental model good enough to predict new cases. None implies the others, which is why shipping SHAP for every prediction can meet a contract and still leave an applicant unable to act; Rudin’s argument is that high-stakes decisions should use models that are interpretable in the first place.

A documented case

The agent that reported deleted

Source: Chapter 5, “Back to Ash”; Shapira et al. 2026 (arXiv:2602.20021); review deck “Chapter 5: Model Explainability”.

A user gives an agent access to email and asks for a sensitive email to be deleted. The agent resets a password, renames an alias, works on the local mail setup, and reports that the secret has been deleted. The email still sits on the provider’s servers, in backups, a recovery window and sync copies the agent could not reach. The failure is in the report, and an attribution that traces the commands to the local changes would be correct and silent about the gap. The provider-side details come from a red-teaming study and are flagged for checking against the primary source.

Conceptual illustration

Explainable to whom?

Language game, mismatch, audience question

Source: Chapter 5, “A short detour through Wittgenstein” and “Back to Ash”; Wittgenstein 1953; Shapira et al. 2026.

The word deleted means different things in two language games. In the agent’s game it means its own scope was wiped; in the user’s game it means no one can reach the data any more. The report is true in the first game and false in the second, so the agent did not lie; the games differed. The check is the audience question: who is reading this, what does the word mean to them, and does the report serve that? Here the report the user needed would say the local state is consistent with deletion, the data may persist on the provider’s servers, and provider-side action is required.

The trade-off

One guarantee out of four claims

Source: Chapter 5, “Where this leaves us”; review deck “Chapter 5: Model Explainability”, “The trade-off”.

A post-hoc explanation method buys coverage and generality: a faithful, model-agnostic number on every prediction. It guarantees one thing, that the attributions add up. It does not guarantee that they are causal, that they are correct about the world, or that they mean anything in the reader’s language game. So these methods work for an auditable description of what the model did, and fail for the usual real question, whether the model is right about the world.

Conceptual illustration

Tell them apart

Look-alike pairs

Source: Chapter 5.

Four pairs of look-alike ideas. An attribution is a number about the model’s accounting, while a causal effect is measured by setting the variable. Marginal SHAP draws features independently, while conditional SHAP draws them given the known ones. Explainable means each output has a reason, while interpretable means a person can predict new cases. The model’s counterfactual is what the model would decide, while the world’s counterfactual is what would actually happen.

Vague request, exact instruction

Say it exactly

Source: Chapter 5, worked example and Exercise A5.

Five vague requests become exact ones, each with a computed check. Explaining a prediction becomes listing Shapley values that sum to 0.17. Saying zip code matters becomes saying it moved the output 0.035 above average, which is not a causal claim. A different LIME answer becomes twenty seeded runs and the spread of the slope; calling a system explainable becomes naming the property and the audience, and asking whether zip is a proxy becomes reporting marginal and conditional values side by side.

Conceptual illustration

Limits

What would change my mind

Source: Chapter 5, “What would change my mind” and “Still puzzling”; review deck “Chapter 5: Model Explainability”.

One thing would weaken the central claim: a feature-attribution method shown to be faithful to causal rather than associative structure, robust to confounding, and able to separate the first rung from the second on observed data alone. Work on causal feature importance is where it might come from, and that status is flagged for verification. A practical gap also remains: the audience check needs someone who knows both the model’s language game and the user’s, and the infrastructure to do that at scale does not exist yet.

Conceptual illustration

Checklist

Before you trust an explanation

Source: Chapter 5, “Where this leaves us”.

Six checks come before trusting an explanation. Does it describe the model or claim something about the world, and which rung is it on? Do the values add up, was the sampling marginal or conditional, and is the result stable when run again? Which property was promised, transparency, explainability or interpretability, and to whom; and who is reading it, and what do its words mean in their game? Then say it exactly: not that it explains itself, but that zip moved the output 0.035.
